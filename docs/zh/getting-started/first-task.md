# 第一个有用任务

[English: First useful task](../../getting-started/first-task.md)

我用一个本地项目和一个小型工程任务演示路由、项目范围、工具确认和运行记录。

## 1. 注册项目

我打开 Settings → Projects，使用绝对路径添加已有仓库，并设置简短名称。
我把项目放在我愿意让工具检查或修改的目录中。

## 2. 打开项目会话

我创建新 Chat 并选择项目，然后提出一个有明确结果的受限任务，例如：

    检查 README，列出构建和运行这个项目所需的三个命令。不要修改文件。

先做只读请求，可以让我确认项目工作区是否正确。

## 3. 尝试受控修改

只读请求成功后，我会提出一个包含验收标准的小修改，例如：

    在 README 增加简短的“开发”章节。保留现有结构，使用仓库的包管理器，
    写出真正启动服务的命令，并运行相关文档检查。

工具需要确认时，我会先检查确认卡片再允许执行。

## 4. 观察 Harness

运行过程中，我可以看到任务类型、模型、工具调用、委派和最终结果。对于较大
任务，我会让 Agent 委派一个边界明确的子任务，再把子 Agent 结果与父 Agent
总结进行对照。

## 5. 检查结果

我会自己检查项目 diff。如果任务通过 Workflow 执行，我会打开
Workflows → Runs，检查节点状态、输出和审计事件。运行记录是执行证据，不是
替代代码审查的理由。
