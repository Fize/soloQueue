# 定时任务

[English: Scheduled tasks](../../guides/scheduled-tasks.md)

我使用 Cron 页面创建周期性或一次性任务。它们与交互式请求共享会话、Team、
模型路由和工具策略。

## 创建任务

1. 我打开 Scheduled tasks。
2. 我选择任务类型、Agent/Team、Prompt 和计划。
3. 如果任务需要仓库上下文，我添加项目路径。
4. 我保存任务并检查下一次运行时间。
5. 我用历史视图检查状态和输出。

我会先创建只读报告或健康检查。确认定时运行稳定后，再添加写入或消息投递操作。

## 渠道通知

当我为 Agent 配置匹配的 notify channel 时，我可以通过 QQ 或微信活动桥接发送
Cron 结果。服务重启后，我需要重新交互才能建立活动发送器。

通知投递是尽力而为的。渠道缺失、过期或限流都可能丢消息，因此我以 Web UI
和 Cron History 作为最终记录。

## 排查漏跑

- 我确认服务进程在计划时间仍然运行。
- 我检查任务是否启用、计划和实际解析模型。
- 我检查 Cron History 和服务日志。
- 我确认 Agent 的 notify_channel 和近期渠道活动。
- 我先交互式重跑 Prompt，再修改计划。
