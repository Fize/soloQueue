# 上下文与记忆

[English](../context-and-memory.md) | 简体中文

SoloQueue 将不同生命周期的状态分开管理：活动上下文窗口是当前模型轮次的输入；时间线是持久化的对话与事件历史；每日对话记忆是短期摘要；记忆引擎则选择性保存可检索的长期事实。

## 状态分层

| 层次 | 主要实现 | 用途与生命周期 |
| --- | --- | --- |
| 活动上下文 | `internal/memory/ctxwin` | 提供给模型的内存消息序列；恢复会话时从时间线重建。 |
| 时间线 | `internal/memory/timeline` | 追加写入的 JSONL 事件，用于历史展示和上下文重放。 |
| 对话记忆 | `internal/memory/conversation` | 按日期命名的 Markdown 摘要，保留近期内容。 |
| 长期记忆 | `internal/memory/engine` | 写入共享 SQLite 并按作用域索引的事实，用于语义、关键词和实体检索。 |

这些层彼此关联，但不能相互替代。上下文压缩摘要不等于完整时间线，长期记忆引擎也不是逐字对话档案。

## 活动上下文窗口

### 消息计数与容量

`ContextWindow` 在 `RWMutex` 保护下保存带类型的消息、时间戳、工具调用元数据、附件和临时标记。Token 统计包含消息正文、推理内容和序列化后的工具调用。`maxTokens` 是模型上下文硬上限；`bufferTokens` 为模型输出预留空间；`summaryTokens` 是触发后台摘要的软阈值。未配置软阈值时，会根据模型窗口大小推算：较小窗口采用 85%，达到大窗口阈值及以上时采用 75%。

每次 Push 都会估算新消息 Token。单条超长消息可能先被截断；超过硬容量时会同步淘汰内容：先从中部截断，再按轮次移除历史。如果超过软阈值且存在 Compactor，则调度一次异步压缩。`BuildPayload` 返回消息副本，并在请求 Provider 前过滤不完整的 assistant 工具调用/工具结果配对，避免将损坏的工具历史发送给 API。

路由选出的模型容量不同时，Session 会调整上下文窗口大小。Provider 调用边界会构建 Payload 并校准 Token 统计；在可用时也会依据 Provider 返回的实际用量修正计数。

### 上下文压缩

自动压缩先复制当前消息快照，让正常 Push 不必等待 LLM 摘要。摘要输入会去除过大的工具输出和已召回记忆块，按自然日分组，再按 Token 预算切分过大的日期组。连续性锚点会把上一份压缩状态带入新摘要，避免活跃目标和未完成工作在多次压缩后丢失。

LLM Compactor 使用配置的快速模型，不把推理内容放入摘要输入，并要求生成结构化状态摘要。代码会校验必需标题和非空的当前目标、清理意外生成的推理块，并拒绝无效摘要。七天内各段摘要会合并为活动上下文；较早的段落通过持久化 Hook 保留。最近实际使用过的 Skill 指令可在压缩后恢复，让模型继续看到有效的工作流说明。

只有生成可用摘要后才会替换上下文。ContextWindow 会将摘要与快照期间新追加的消息协调合并，然后在锁外调用 Summary Hook。如果压缩失败或没有有效的近期摘要，原上下文不会被空状态覆盖。

## 时间线与会话恢复

Session 的 Push Hook 会将消息事件追加到 `logs/timelines/` 下的 JSONL 时间线。事件保留角色、时间戳、工具调用/结果、文件、Request ID 等元数据；控制事件标记压缩或清空等边界。系统 Prompt 会加入内存上下文，但有意不写入时间线。

构建会话时，SoloQueue 先载入系统 Prompt，再读取最近一次压缩/清空边界后的时间线片段并重放到上下文窗口。重放会跳过不完整的工具调用/结果配对。Web Console 的历史分页读取与上下文恢复使用同一时间线，但分页读取不受上下文重放限制影响。

清空会话会重置活动上下文并保留系统 Prompt，同时在时间线上记录清空边界；已有时间线文件不会删除。压缩会用摘要替换活动上下文中的较早内容，但持久化事件历史仍然保留。

## 对话记忆

对话 `Manager` 将 Markdown 写入 `<workdir>/memory/` 下按日期命名的文件。记录近期时间线片段时，快速模型会将新内容与当天文件合并；写入采用临时文件后重命名的方式。基于消息时间的游标用于避免重复记录。系统 Prompt 会提供记忆目录位置，并要求 Agent 仅在相关时通过 Read/Grep 读取；文件内容不会直接嵌入 Prompt。超过保留期的日期文件会被清理。

在 L1 路径中，上下文 Summary Hook 还会向时间线写入一条合并后的摘要事件。七天以内的片段可以写入短期对话记忆；更早的片段仍保留在时间线，其中提取出的持久 `<memories>` 候选还可能写入长期记忆引擎。L2 的摘要 Hook 以时间线记录为主，不使用 L1 的对话记忆写入流程。

## 长期记忆引擎

### 写入准入与所有权

长期记忆与每日 Markdown 摘要相互独立。引擎在存储前校验候选内容、所有者、作用域、类型、来源、时间字段和替换元数据，并对内容规范化后去重。自动候选有长度限制；普通任务结果会被跳过，除非用户明确要求保存。支持的类型包括偏好、决策、稳定事实和可复用方案。

Agent 工具拿到的是绑定所有者和作用域的不可变 `Access` 能力，而不是拥有全部权限的 Engine。L1 与 L2 群组分别绑定访问范围；所有者和作用域由服务端附加到写入和检索请求中，工具无法仅靠修改查询参数任意选择数据所有者。

### 检索流程

混合检索器并行运行 BM25、知识图谱和（配置后）向量搜索。它通过 Reciprocal Rank Fusion 合并排序结果，从权威记忆存储中补齐内容，再按时间、生命周期状态和作用域过滤，应用查询时的显著性衰减，最后截取请求数量。实体查询还可以附带相关图边。

BM25 与知识图谱不依赖 Embedding Provider。只有配置并成功创建 Embedding Provider/模型时，运行时才启用向量检索。如果向量存储无法执行所有者/作用域过滤，向量检索会关闭返回，以避免越权。共享 SQLite 保存记忆条目和图数据；启用向量检索时，向量记录也写入该共享数据库中的配置表。

## 存储位置与代码索引

- `<workdir>/logs/timelines/`：追加式会话事件与重放边界。
- `<workdir>/memory/`：近期 Markdown 对话摘要。
- `<workdir>/soloqueue.db`：引擎及其他运行时子系统使用的共享 SQLite 数据。
- [`internal/memory/ctxwin`](../../internal/memory/ctxwin)：Token 窗口、淘汰、压缩与 Payload 清理。
- [`internal/memory/timeline`](../../internal/memory/timeline)：JSONL 写入、读取和重放。
- [`internal/memory/conversation`](../../internal/memory/conversation)：每日摘要合并与保留期管理。
- [`internal/memory/engine`](../../internal/memory/engine)：候选准入、作用域、混合检索和生命周期。
- [`internal/runtime/build_memory.go`](../../internal/runtime/build_memory.go)、[`internal/session/builder.go`](../../internal/session/builder.go)：装配并连接这些层次。
